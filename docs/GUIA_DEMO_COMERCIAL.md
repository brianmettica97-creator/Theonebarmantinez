# Cómo presentar la demo

**Mensaje:** "Esta es una propuesta de NOVANTIQ con contenido de ejemplo; con sus datos y fotos reales queda lista para publicar."

## Preparación (5 min)
1. `npm run dev` (o publicar `dist/` en un hosting estático para compartir el link). Abrir en el celular del cliente si es posible.
2. Para mostrar el flujo de WhatsApp: panel → Ajustes → cargar **tu propio número de prueba** (no el del cliente) y guardar. Al terminar, vaciar el campo.
3. Si hace falta, panel → Ajustes → *Restablecer datos de demostración*.

## Recorrido sugerido (8–10 min)
1. **Celular:** portada → barra inferior (Carta, Promos, Juegos, Reservas, Contacto).
2. **Carta:** categorías, búsqueda, un producto *agotado*; agregar 2 productos → pedido → mostrar el aviso honesto ("abrir WhatsApp no es enviar") y el mensaje generado.
3. **Promociones:** explicar que la vencida y el borrador **no se muestran**.
4. **Reservas:** enviar una solicitud → queda *pendiente* (no confirmada).
5. **Panel:** cambiar un precio y marcar un producto no disponible → recargar la web y verlo. Crear una promoción con fechas. Cambiar el estado de la reserva.
6. **Cierre:** ajustes (logo, color, horarios), roadmap (pedidos con seguimiento, The One Club).

## Qué decir y qué no
- Decir: todo marcado "Ejemplo" es ilustrativo; faltan sus datos, logo y fotos; pagos y fidelización son etapas posteriores.
- No prometer: reservas confirmadas automáticamente, pedidos que "llegan solos", pagos, fidelización ni plazos sin definir reglas con el negocio.
- En la demo local los datos viven en el navegador: no compartir el panel como si fuera un sistema multiusuario.

## Para cerrar el proyecto
Pedir: logo/paleta, fotos, carta real, WhatsApp/horarios/dirección, confirmación de actividades y eventos privados, autorización de publicación. Ver [ENTREGA](ENTREGA.md).
